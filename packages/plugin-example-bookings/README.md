# Bookings: an example Lintel plugin

A small appointments app, kept as the reference for writing plugins. It uses most of what
a plugin can do; the docs page "Writing a plugin" walks through it step by step.

- **Server** (`src/server`, exported as `./server`): the `bookings` table and migration,
  routes to list, add, change and cancel bookings, the `bookings:read` and
  `bookings:manage` permissions, a setting (the usual length of a booking), and its
  personal data: which columns hold it, and the hooks Settings → Privacy uses to find,
  export and erase one person's bookings (`bookings.personal-data.ts`).
- **Admin** (`src/admin`, exported as `./admin`): a **Bookings** sidebar item with a list
  and a form, a **Today's bookings** dashboard widget, a **Bookings this week** tab on the
  dashboard, and Settings → Bookings.

It is listed in `lintel.config.ts` at the repository root, so it appears in Settings →
Features, switched off. Remove it from that list for a real site.

## Routes

Every route answers 404 `PLUGIN_NOT_ENABLED` while the plugin is off (Lintel does that).

| Method and path        | Permission        | Body                                                                         |
| ---------------------- | ----------------- | ---------------------------------------------------------------------------- |
| `GET /bookings`        | `bookings:read`   | `?from=&to=` (dates and times) -> `{ bookings }`, earliest first             |
| `GET /bookings/:id`    | `bookings:read`   | none                                                                         |
| `POST /bookings`       | `bookings:manage` | `{ customerName, customerEmail, startsAt, durationMinutes?, notes? }` -> 201 |
| `PATCH /bookings/:id`  | `bookings:manage` | any of those                                                                 |
| `DELETE /bookings/:id` | `bookings:manage` | none -> 204                                                                  |

## Commands

```bash
pnpm --filter @lintel/plugin-example-bookings test         # the routes, against a real server
pnpm --filter @lintel/plugin-example-bookings db:generate --name <what_changed>
pnpm --filter @lintel/plugin-example-bookings build        # the server half, to dist
```

`db:generate` reads `@lintel/core/plugin` from its build, so run
`pnpm --filter @lintel/core build` first.

## Databases

It runs on the built-in database, Postgres, MySQL and MariaDB. After changing a table, run
`pnpm db:generate --name <what_changed>` and then `pnpm db:generate:mysql --name <what_changed>`.
Its queries get their tables through `tableFor`, and `lintel addons check` reads them for
anything only Postgres has. `pnpm test:addons` in `packages/core` runs its tests on real servers.
